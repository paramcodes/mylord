## Agent orchestration (managed block)

The region between the `orchestration:begin` and `orchestration:end` markers is generated by the
`orchestration-init` skill. Re-running the skill rewrites only that region. Hand-written rules
outside the markers are never touched.

### Roles

- The main agent is a **coordinator**, not an implementer. It plans, spawns subagents, tracks
  state, and reports. It does not write feature code when a subagent can.
- Implementation goes to background subagents. One subagent owns one issue and one worktree.
- The reviewer-merger and the reconciler are always separate agents from the implementer.

### Workflow per issue

1. Cut a branch from `origin/main`. Never branch from a stale local branch.
2. Work in the item's own worktree at `/home/param/Work/mylord-wt/<item>`, not in the primary checkout.
3. Commit in small focused commits. Each commit's estimated diff stays under
   5000 tokens, lockfiles excluded.
4. No comments except where technically required. Explain "why" in the PR, not in the code.
5. Run the gates in order from the repo root:

   ```sh
   bun install
   bun run typecheck
   bun run test
   bun run lint
   bun run build
   ```

   Lint always runs before build. Skip a gate only when it has no command, and say so in the PR.
6. Push the branch and open a PR with `gh pr create`. The body states What / Why / How and ends
   with `Closes #<issue>`.
7. A separate reviewer subagent inspects the diff, re-runs the gates on the rebased branch, then
   squash-merges with `gh pr merge <n> --squash` and deletes the remote branch.
8. After merge, a reconciler subagent fast-forwards the local default branch to
   `origin/main` and updates the queue file.

### Parallelism

- Keep at least three subagents in flight. Refill the queue the moment one finishes. Treat that as
  a floor, not a target: back off when the provider returns rate-limit errors.
- Split the fleet by cost. Read, plan, review, and research agents run on the provider and use no
  local CPU. Gate-running agents — install, typecheck, test, lint, build — use local CPU, memory,
  and disk.
- Cap concurrent gate-running agents at 2. Agents over the cap keep working
  on non-gate work while they wait.
- Never start a gate run while the one-minute load average is above twice the physical core count,
  or available memory is under 1 GiB. Queue the run instead.
- Never run two subagents that edit the same file or package at the same time.
- Before dispatching a batch, list the files each item will touch and intersect the lists. Two items
  that overlap anywhere are dependent; run them in sequence.
- Independent items — different packages or files — run concurrently. A dependent item waits for
  its parent to merge.
- The queue lives in `todos.md`. An item moves to `[x]` only after its PR merges.

### Concurrency safety

- Branches are always created from `origin/main`, never from the local branch, so a
  worktree cannot diverge from the remote.
- Remote merges are squash merges. The local default branch is only ever fast-forwarded.
- Never force-push. Never commit directly to `main`.
- If the local branch diverges from `origin/main`, a reconciler agent resolves it
  before any new branch is cut.

### Commit hygiene

- One logical change per commit.
- Keep each commit's estimated diff under 5000 tokens, lockfiles excluded.
- Use conventional commit messages.

### Tests and evidence

- Every change carries tests, or the PR states why it cannot.
- A visual change needs a screenshot or GIF. A performance change needs measured numbers.
- Evidence is attached to the PR as a comment before merge.

### Escalation

- Ask the operator instead of guessing when the queue has no unblocked items, two items conflict on
  files and neither can be re-scoped, a gate has no command and the change cannot be verified, the
  host cannot keep up with the gate queue, or a PR fails review twice for the same reason.

### Delegation

- Merges, queue updates, issue creation, PR descriptions, and evidence collection are delegated to
  subagents.
- The coordinator keeps replies short: status, blockers, next batch.
